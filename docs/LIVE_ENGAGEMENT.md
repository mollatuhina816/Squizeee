# Live engagement

In the presentation editor, select **Presenter-paced**, optionally enable **Team competition** and **Streak multipliers**, save the slides, then select **Present**. Live options apply to the new session. Existing sessions and API clients that omit options keep self-paced behavior.

- **Shared questions:** Open question → Close answers → Reveal answer → Next question. Opening the next slide starts its own timer. Pause/resume freezes the authoritative timer and rejects submissions during the pause. Reopening preserves the deadline and is blocked after revealing the answer.
- **Scoring:** Correct answers earn marks plus a linearly decreasing speed bonus. New editor questions default to a 1-point maximum speed bonus, editable in question settings. With streaks enabled, the third and fourth consecutive correct answers earn 1.5×, and the fifth onward earn 2×. Incorrect, ungraded or skipped questions break the streak. Scores are stored once as integer thousandths; negatives are never multiplied. Profile maximum scores include the possible multipliers.
- **Teams:** New participants join the smallest of four color-coded teams. The team leaderboard uses average points across every member, including members with zero points. Assignment is serialized by the session lock. Empty teams do not outrank active teams.
- **Reactions:** Participants send ❤️, 👏, 🔥 or 😂. Redis publishes these transient events to connected displays. Reactions are rate limited, bounded in the browser and intentionally not replayed after a reconnect.
- **Audience Q&A:** Participants submit questions up to 500 characters. Hosts approve, hide or mark them answered. Approved questions rise by vote count. A database composite key limits each participant to one upvote per question; self-votes and cross-session access are rejected. Pending questions are visible only to their author and authorized hosts. The audience board is separate from quiz slides.
- **Formats:** Word clouds normalize case and count Unicode words; repeated words grow in the display. Ranking supports mouse drag/drop and accessible up/down controls; specify a correct order for grading or leave it blank for audience preference rankings. Scales render selectable numeric ratings, including 1–5 and 1–10. Pin on Image accepts an HTTPS image URL and a circular target in normalized coordinates; participants tap or enter coordinates, hosts see submitted pins, and the target appears on reveal.
- **Random spotlight:** The server uses a secure random choice across the joined participant roster and publishes the result. The wheel animates the selection. This draws from all joined participants, including disconnected participants; it is not an attendance detector.
- **Guests:** QR/PIN entry offers nickname-only participation with a session-specific credential. Rejoining from the same browser reuses that credential. Guest attempts are not attached to a reusable student profile. Student-profile entry remains available and hosts can disable guests.
- **Remote:** Open **private remote** from the host display. The authenticated controller shows notes for the current slide, upcoming-question preview, counts, timer controls and moderation. Notes and unrevealed answer targets are excluded from participant snapshots and socket broadcasts.

WebSockets carry snapshots and transient events through Redis; REST refresh recovers durable state after reconnects. Timers and scoring use server time. Local development QR links require a hostname reachable by the phone; `localhost` resolves to the phone itself. Production latency and large-audience capacity require deployment/load testing; local functional tests do not establish a latency guarantee.
